## 1. 한눈에 보기

```
① /admin 에서 GitHub 계정으로 로그인
② 왼쪽 메뉴에서 항목을 고르고 추가·수정·삭제
③ '확인하고 게시' → 바뀌는 칸을 이전 값과 나란히 보고, 화면 미리보기 확인
④ '게시하기' → GitHub 저장소 main 에 저장(커밋)
⑤ 1~2분 뒤 공개 사이트에 반영 (관리자 화면 위쪽에 반영 상태 표시)
```

- 따로 있는 데이터베이스나 서버는 없습니다. **모든 내용은 GitHub 저장소 안의 파일로 저장됩니다.**
- 관리자 승인 단계도 없습니다. 편집자가 직접 확인하고 게시하며, 누가 언제 무엇을 바꿨는지는 모두 변경 기록에 남습니다.
- **저장소가 공개 상태라는 점을 늘 기억해 주세요.** 올린 글과 사진은 누구나 볼 수 있습니다. 지워도 변경 기록에는 남습니다.

### 2-3. 사진 규격

사진은 올리는 순간 브라우저 안에서 아래 크기의 JPEG 로 줄여 저장됩니다. 이때 촬영 위치(GPS) 같은 사진 속 정보(EXIF)는 지워집니다.

| 사진 | 처리 방법 | 저장 크기 |
|---|---|---|
| 구성원·졸업생 프로필 | 세로 4:5로 자름 (위쪽 기준) | 900 × 1125 |
| 소식 대표 사진 | 비율 유지 | 긴 변 1600 이하 |
| 저역서 표지 | 비율 유지 | 900 × 1350 이하 |
| 논문 초록 이미지 | 비율 유지, 글자가 잘 보이게 고화질 | 가로 1600 · 세로 3200 이하 |
| 연구 과제 대표 이미지 | 가로 4:3으로 자름 | 1200 × 900 |

- 올릴 수 있는 파일: JPG·PNG, 30MB 이하. 아이폰 HEIC 사진은 JPG 로 바꿔서 올립니다.
- **본인이 게시에 동의한 사진만** 올립니다. 공개 저장소라 지워도 변경 기록에는 남습니다.

### 2-4. 자주 헷갈리는 규칙

- **날짜 형식이 메뉴마다 다릅니다.**
  - 소식: `2026-11-09` (하이픈)
  - 논문·저역서·학술발표: `2026.08` (점)
  - 연구 과제: `2026.03` (점)
- **주소와 번호는 한 번 정하면 바꿀 수 없습니다.** 소식·구성원·졸업생의 주소는 사이트 주소(`/people/seoyeon-lee`)가 되므로 처음에 신중히 정합니다. 꼭 바꿔야 하면 새로 추가한 뒤 예전 항목을 삭제합니다.
- **번호는 게시할 때 확정됩니다.** 편집 중에 보이는 번호는 예상값입니다. 다른 사람이 먼저 같은 번호로 게시했으면 다음 번호가 붙습니다.
- **자동으로 계산되는 값은 입력 칸이 없습니다.** 아래 값들은 관리자 화면이 저장할 때 맞춥니다.
  - 논문·저역서·학술발표: 연도와 정렬값
  - 연구 과제: 기간 표기와 시작·종료 연도
  - 실적 종류별 건수
- **삭제하면 공개 사이트에서 바로 사라집니다.** 그 항목 전용으로 올린 사진도 함께 지워집니다. 변경 기록에는 남으므로 되살릴 수 있습니다([3-4](#3-4-게시-기록과-되돌리기) 참고).
- **구성원이 졸업하면** 그 구성원의 편집 화면 오른쪽 위에서 **졸업생으로 옮기기** 를 누릅니다.
  - 졸업생 입력 폼이 미리 채워진 채로 열립니다. 그대로 옮겨지는 것은 주소(`/people/<주소>`), 이름, 영문 이름, 프로필 사진, 연구 분야, 상세 프로필 네 목록입니다.
  - 학위는 과정에 맞춰 미리 골라져 있습니다(박사과정 → 박사, 그 밖 → 석사). 졸업 연도는 올해로 들어가 있습니다. 둘 다 확인합니다.
  - 학위논문을 적습니다. 현재 소속은 본인이 공개에 동의한 경우에만 적습니다.
  - 이력에 ‘현재’로 적힌 줄(예: `2025.03 – 현재` 석사과정)은 졸업에 맞게 고칩니다.
  - **확인하고 옮기기** → **옮기기** 를 누르면 한 번에 처리됩니다. 구성원 목록에서 빠지고 졸업생 목록에 들어가며, 기록에는 `[CMS] 구성원 → 졸업생 옮김: 이름` 으로 남습니다.
  - 졸업생 정보에 없는 칸(과정, 입학·합류, 공개 이메일, 연구 관심사, 소개)은 옮기지 않습니다. 화면에서 어떤 칸이 빠지는지 미리 알려 줍니다.
  - 옮기는 사이 다른 사람이 그 구성원 정보를 고쳤으면 알림이 뜹니다. **최신 내용 불러오기** 를 누르면 바뀐 정보를 다시 채우고, 내가 적은 학위·학위논문 같은 칸은 그대로 둡니다.
- **예시 항목**(‘예시’ 배지가 붙은 가상 소식·구성원·졸업생)은 레이아웃 확인용입니다. 실제 내용을 입력한 뒤 삭제합니다.
- **임시 저장.** 쓰던 내용은 그 브라우저에 자동으로 임시 저장됩니다. 창을 닫았다가 같은 항목을 다시 열면 “게시하지 않은 수정 내용이 있습니다” 안내가 나옵니다. 여기서 **불러오기** 또는 **버리기** 를 고릅니다. 다른 PC나 다른 브라우저에서는 보이지 않습니다.
- **여러 명이 동시에 고쳐도 됩니다.** 같은 항목이라도 다른 칸을 고쳤으면 게시할 때 자동으로 합쳐집니다. 같은 칸을 둘 다 고친 경우에만 ‘최신 내용 불러오기’와 ‘내 내용으로 덮어쓰기’ 중 하나를 고르라고 묻습니다.

### 2-5. 관리자 화면으로 아직 고칠 수 없는 것

아래 내용은 지금은 파일을 직접 고쳐야 합니다. 관리자 화면에서 고칠 수 있게 하는 작업(사이트 문구 편집)은 다음 단계로 계획되어 있습니다.

| 주소·호실·전화·이메일, 상단 메뉴, Contact 의 참여 안내 문답 | `content/site.ts` |
| 지도교수 소개·학력·연락처 | `content/profile.ts` |

| 색·글꼴·간격 등 디자인 | `design-system/tokens.json` → `npm run tokens` |

## 3. 데이터 저장 위치

### 3-1. 게시한 내용 — GitHub 저장소의 파일

| 메뉴 | 데이터 파일 (파일 안의 목록) | 사진 폴더 |
|---|---|---|
| 소식 | `content/data/news.json` (`items`) | `public/images/news/` |
| 구성원 | `content/data/members.json` (`members`) | `public/images/people/` |
| 졸업생 | `content/data/members.json` (`alumni`) | `public/images/people/` |
| 논문 | `content/data/publications.json` (`items` 중 `type: "journal"`) | 초록 이미지 `public/images/abstracts/` |
| 저역서 | `content/data/publications.json` (`items` 중 `type: "book"`) | 표지 `public/images/books/` |
| 학술발표 | `content/data/publications.json` (`items` 중 `type: "conference"`) | — |
| 연구 과제 | `content/data/projects.json` (`items`) | `public/images/projects/` |

- 사진 파일 이름은 `<주소 또는 번호>-<임의 글자>.jpg` 입니다(예: `seoyeon-lee-m3k2x1.jpg`). 사진을 바꿀 때마다 새 이름을 써서, 브라우저에 남은 예전 사진이 보이지 않게 합니다.
- 관리자 화면은 **위 표의 데이터 파일과 사진 폴더만** 고칩니다. 사이트 코드, 디자인, 그 밖의 파일은 건드리지 않습니다.
- 저장소 주소: `https://github.com/smu-edtech-lab/lead-ai-lab`

### 3-2. 게시 전 — 내 브라우저에만

| 무엇 | 어디 | 언제 지워지나 |
|---|---|---|
| 쓰던 내용(임시 저장) | 그 브라우저의 저장 공간 | 게시하거나, 다시 열었을 때 ‘버리기’를 누르면. 다른 PC·브라우저에는 없음 |
| 로그인 정보 | 그 브라우저 탭 | 탭을 닫으면, 또는 로그인 8시간 뒤 자동 만료 |

게시하기 전의 내용은 저장소에도, 다른 사람에게도 보이지 않습니다. 공용 PC 에서는 다 쓴 뒤 탭을 닫아 주세요.

### 3-3. 게시한 뒤 — 사이트에 반영되는 과정

```
저장소 main 에 커밋
  → GitHub Actions(.github/workflows/deploy.yml)
      1) 데이터 검사 (npm run check:data — 빠진 칸, 없는 사진 파일, 잘못된 형식)
      2) 사이트 빌드
      3) GitHub Pages 에 배포
  → 1~2분 뒤 공개 사이트에 반영
```

- 관리자 화면 위쪽에 ‘사이트에 반영하는 중…’ 또는 ‘사이트 반영 실패 — 확인 필요’가 표시됩니다.
- 검사에 실패해도 공개 사이트는 **이전 상태 그대로** 유지됩니다. 표시를 누르면 실패 원인이 적힌 GitHub Actions 기록이 열립니다.

### 3-4. 게시 기록과 되돌리기

- 게시할 때마다 저장소에 기록(커밋)이 하나씩 남습니다. 제목은 `[CMS] 소식 추가: 제목` 같은 형식이고(여러 건을 한 번에 게시하면 `… 외 2건`), 게시한 사람의 GitHub 계정이 함께 남습니다.
- 공개 저장소에 이메일 주소가 드러나지 않도록, 기록에는 `<번호>+<아이디>@users.noreply.github.com` 형식의 GitHub 대체 주소가 쓰입니다.
- 이전 내용 보기: 저장소 → **Commits** → `[CMS]` 로 시작하는 기록을 누릅니다.
- 되돌리기: 보통은 관리자 화면에서 다시 고쳐 게시하면 됩니다. 삭제한 항목은 위 기록에서 예전 값을 보고 다시 추가합니다.

### 3-5. 공개 범위 — 올리기 전에 확인할 것

저장소가 공개 상태이므로, 관리자 화면에 입력한 모든 값은 사이트에 나오지 않는 값까지 누구나 볼 수 있습니다. 숨긴 프로필 줄과 예전 기록도 마찬가지입니다.

- 넣지 않는 것:
  - 학번, 생년월일, 집 주소, 개인 휴대전화
  - 본인이 동의하지 않은 이메일·소속·사진
  - 비공개 과제 정보, 심사 중인 논문의 내용
- 사진과 개인 정보는 **본인 동의를 받은 것만** 올립니다.
- 실수로 개인 정보를 올렸다면 관리자 화면에서 지우는 것만으로는 기록에서 사라지지 않습니다. 바로 저장소 관리자에게 알려 주세요. 기록에서까지 지우는 일은 관리자가 따로 처리해야 합니다.

## 4. 편집자 권한

관리자 화면에는 따로 회원 명단이 없습니다. **GitHub 저장소 권한이 곧 관리자 화면 권한입니다.**

| 누구 | GitHub 저장소 권한 | 할 수 있는 일 |
|---|---|---|
| 방문자 | 없음 | 공개 사이트 보기. `/admin` 에 들어와도 로그인 화면만 보임 |
| 초대받지 않은 GitHub 사용자 | 없음 (Read) | 로그인해도 “이 저장소를 고칠 권한이 없습니다” 안내만 보이고 들어갈 수 없음 |
| **편집자** | **Write** (협업자) | 관리자 화면의 모든 메뉴에서 추가·수정·삭제·순서 바꾸기 후 바로 게시 |
| **저장소 관리자** | 저장소 **Admin** 또는 조직 **Owner** | 편집자 일 전부 + 편집자 초대·제거, 저장소 설정, 보호 규칙, 로그인 설정 관리 |

- 편집자끼리는 권한 차이가 없습니다. 관리자 승인 단계도 두지 않았습니다(2026-11-10 연구실 결정).
- 승인 단계 대신 아래 장치가 실수를 막고, 실수해도 되돌릴 수 있게 해 줍니다.
  - 게시 전 확인 창: 바뀐 칸을 이전 값과 나란히 보여 주고 미리보기도 함께 보여 줌
  - 게시 기록: 모든 게시가 누가 했는지와 함께 남음
  - 칸 단위 자동 병합: 다른 사람이 다른 칸을 고친 것은 덮어쓰지 않음
  - 배포 전 데이터 검사: 검사에 실패하면 사이트가 바뀌지 않음
  - 보호 규칙(권장): 기록을 지우거나 덮어쓰지 못하게 함 — 설정 안내 9단계
- **Write 권한은 관리자 화면 밖에서도 힘이 있습니다.** GitHub 웹사이트에서 저장소의 코드와 디자인 파일을 직접 고칠 수 있는 권한이기 때문입니다. 관리자 화면 자체는 데이터 파일과 사진만 건드리지만, 편집자로는 **연구실 구성원 등 믿을 수 있는 사람만** 초대해 주세요.

### 편집자 추가·제거

자세한 화면 순서는 [설정 안내 8단계](CMS-설정-안내.md#8-편집자-추가제거-사람이-바뀔-때마다)에 있습니다.

1. 새 편집자는 GitHub 계정을 만들고(무료) 아이디를 저장소 관리자에게 알려 줍니다.
2. 저장소 관리자가 저장소 → **Settings** → **Collaborators and teams** → **Add people** 로 초대합니다. 역할은 **Write** 입니다.
3. 새 편집자가 초대 메일의 **수락** 버튼을 누릅니다. 이 단계를 빠뜨리면 로그인해도 권한이 없다고 나옵니다.
4. 졸업이나 담당 변경으로 빠지는 사람은 같은 화면에서 **Remove** 합니다. 그 사람이 남긴 게시 기록은 그대로 남습니다.

## 5. 계정과 비밀값

관리자 화면이 동작하는 데 필요한 계정과 설정은 아래가 전부입니다. **비밀값은 저장소 안에 하나도 없습니다.** 공개 저장소이므로 앞으로도 저장소에 넣으면 안 됩니다.

| 계정·설정 | 무엇에 쓰나 | 누가 관리하나 | 비밀값 |
|---|---|---|---|
| **연구실 GitHub 조직** `smu-edtech-lab` | 저장소·사이트 전체의 주인. 조직 소유자(Owner)가 편집자 초대·제거, 설정을 맡음 | 조직 소유자 — **2명 이상** 권장 | 소유자 각자의 GitHub 비밀번호·2단계 인증 (본인만) |
| **편집자 각자의 GitHub 계정** | 관리자 화면 로그인 | 편집자 본인 | 본인 비밀번호 (공유 금지) |
| **GitHub App** `LEAD AI Lab CMS` | 로그인한 사람이 “이 저장소의 콘텐츠만” 고치도록 권한을 좁힘 | 조직 소유로 만듦 (설정 안내 3단계) | Client ID(공개해도 됨), **client secret**(Cloudflare 에만 넣음). 설치에 필요해 만든 private key 는 쓰지 않으며 파일은 보관하지 않음 |
| **Cloudflare 계정**과 Worker `lead-ai-lab-cms-auth` | GitHub 로그인 결과를 관리자 화면으로 돌려주는 중계 서버 (`cms-auth/worker.js`) | 지금은 홈페이지 담당자의 개인 계정. **연구실 공용 이메일 계정 권장** | client secret 을 보관. Cloudflare 비밀번호 |
| 저장소 변수 `CMS_AUTH_URL` | 관리자 화면이 중계 서버 주소를 알게 함 | 저장소 관리자 | 비밀 아님 (Worker 주소) |
| 비상용 토큰 (Fine-grained personal access token) | 중계 서버가 없거나 고장 났을 때 임시 로그인 | 쓰는 사람 각자 | **토큰 자체가 비밀번호입니다.** 짧게(7일 등) 만들고 남에게 보내거나 문서에 적지 않음 |

- GitHub App 과 Cloudflare 는 **처음 한 번만** 만듭니다. 그 뒤로는 편집자 초대·제거만 하면 됩니다. 만드는 방법은 [설정 안내 2~7단계](CMS-설정-안내.md)에 있습니다.
- 로그인 토큰은 8시간 뒤 자동으로 만료되고 탭을 닫으면 지워집니다. 그래서 공용 PC 에서 써도 남지 않습니다.
- client secret 이 새어 나갔다고 의심되면 아래 순서로 바꿉니다. 이렇게 하면 예전 값은 쓸 수 없게 됩니다.
  1. GitHub App 설정에서 새 client secret 을 만듭니다.
  2. Cloudflare Worker 의 `GITHUB_CLIENT_SECRET` 을 새 값으로 바꿉니다.
  3. GitHub App 설정에서 예전 secret 을 지웁니다.

### 연구실 조직 `smu-edtech-lab`

저장소는 2026-11-10 개인 계정에서 연구실 GitHub 조직(Organization, 무료)으로 옮겼습니다. 사람이 바뀌어도 조직과 저장소는 그대로 남습니다.

- **소유자(Owner)를 2명 이상** 두세요. 소유자가 한 명뿐이면 그 사람이 떠날 때 편집자 초대·제거를 할 사람이 없어집니다.
  - 추가 방법: 조직 페이지 `https://github.com/smu-edtech-lab` → **People** → **Invite member** → 역할 **Owner**
- 조직은 로그인용 공용 계정이 아닙니다. 소유자와 편집자 모두 **각자의 GitHub 계정**으로 들어옵니다. 한 계정을 여럿이 나눠 쓰는 것은 GitHub 약관상 허용되지 않습니다.
- 저장소를 다시 옮길 일이 생기면 [설정 안내 11단계](CMS-설정-안내.md#11-저장소를-다른-곳으로-옮길-때)를 봅니다.

## 6. 담당자가 바뀔 때 체크리스트

홈페이지 담당자(저장소 관리자)가 바뀔 때 아래를 넘겨줍니다.

- [ ] 새 담당자를 조직 **Owner** 로 지정 (조직 → **People** → **Invite member**)
- [ ] 떠나는 편집자 **Remove**, 새 편집자 초대 (4장)
- [ ] Cloudflare 계정: 연구실 공용 계정이면 로그인 방법을 넘겨줌. 개인 계정이면 새 담당자를 Cloudflare 계정 구성원으로 초대
- [ ] GitHub App: 조직 소유로 만들었다면 넘길 것 없음. 개인 계정 소유로 만들었다면 조직으로 넘김(App 설정 → **Advanced** → **Transfer ownership**)
- [ ] 이 문서와 [설정 안내](CMS-설정-안내.md)의 위치를 알려 줌 (저장소 `docs/` 폴더)
- [ ] 관리자 화면에 로그인해 보고, 소식 하나를 고쳐 게시해 사이트에 반영되는지 확인
