## 1. 한눈에 보기

### 사이트의 어느 부분을 어디서 고치나

| 사이트 메뉴 | 화면에 나오는 것 | 고치는 곳 |
|---|---|---|
| Home | 최근 소식, 구성원 미리보기 | 관리 화면 › **소식**, **구성원** |
| Home | 첫 화면 문구, 섹션 제목·설명 | 파일 수정 ([8장](#8-디자인레이아웃고정-문구-바꾸기)) |
| About | 지도교수 프로필, 연구실 소개, 비전 | 파일 수정 |
| Research | 주요 연구 분야 설명 | 파일 수정 |
| Research › Publications | 학술지 논문 | 관리 화면 › **논문** |
| Research › Projects | 연구 과제 | 관리 화면 › **연구 과제** |
| Research › Presentations | 학술발표 | 관리 화면 › **학술발표** |
| People | 재학생·연구원, 졸업생 | 관리 화면 › **구성원**, **졸업생** |
| People › 개인 프로필 | 사진, 소개, 연구실적·참여 연구 프로젝트·수상·이력 | 관리 화면 › **구성원**·**졸업생**의 각 항목 |
| Books | 저역서 표지 카드 | 관리 화면 › **저역서** |
| News | 소식 + 최근 논문·저역서의 ‘연구 성과’ 소식 | 관리 화면 › **소식** (연구 성과는 논문·저역서를 추가하면 자동으로 생김) |
| Contact | 주소·연락처, 지원 안내 | 파일 수정 |
| 전체 | 색·글꼴·간격, 메뉴 구성, 페이지 배치 | 파일 수정 |

### 고치는 흐름

```
관리 화면에서 고치기 → [확인하고 게시] → 바뀐 칸 확인 창 → [게시하기]
   → 저장소에 기록 → 자동 검사·빌드 → 1~2분 뒤 공개 사이트에 반영
```

- 승인 단계는 없습니다. 편집자가 바뀐 칸을 확인하고 바로 게시합니다.
- 모든 게시는 **누가 언제 무엇을** 바꿨는지 저장소에 기록되고, 언제든 다시 고치거나 되돌릴 수 있습니다.
- 자동 검사에서 문제가 발견되면 사이트는 바뀌지 않고 이전 상태로 남습니다.

## 2. 처음 시작하기

### 편집자가 되려면 (한 번만)

1. <https://github.com> 에서 GitHub 계정을 만듭니다 (무료). 영문 아이디를 홈페이지 담당자에게 알려 줍니다.
2. 담당자가 초대하면 GitHub 에서 초대 메일이 옵니다. 메일의 **View invitation** → **Accept invitation** 을 누릅니다.
   - 초대는 7일 안에 수락해야 합니다. 지났으면 담당자에게 다시 초대해 달라고 합니다.
   - GitHub 이 2단계 인증(인증 앱 등)을 설정하라고 하면 안내대로 설정합니다.
3. 관리 화면(<https://smu-edtech-lab.github.io/lead-ai-lab/admin>) → **GitHub 계정으로 로그인**
4. 처음 한 번은 GitHub 이 “LEAD AI Lab CMS 가 계정에 접근하려 합니다” 라고 묻습니다. **Authorize** 를 누릅니다.
   다음부터는 묻지 않고 바로 들어갑니다.

### 화면 구성

| 위치 | 있는 것 |
|---|---|
| 위쪽 막대 | **사이트 반영 상태**(초록 = 최신, 주황 = 반영 중, 빨강 = 실패), **사이트 보기 ↗**, **사용 안내 ↗**(이 문서), 내 이름, **로그아웃** |
| 왼쪽 메뉴 | 처음 화면 / 소식·사람(소식·구성원·졸업생) / 연구 실적(논문·저역서·학술발표·연구 과제) |
| 처음 화면 | 메뉴별 항목 수, **목록 보기**, **+ 추가** 버튼, 올리기 전 주의 사항 |
| 편집 화면 | 입력 칸과 공개 사이트와 같은 모양의 **미리보기**(오른쪽, 논문 등은 아래쪽), 맨 아래 **삭제 / 취소 / 확인하고 게시** |

- 로그인은 **8시간 뒤 자동으로 끝나고**, 브라우저 탭을 닫아도 끝납니다. 공용 PC 에서는 다 쓴 뒤 **로그아웃** 하고 탭을 닫으세요.
- 칸 이름 옆 **필수** 표시는 꼭 채워야 하는 칸입니다. 비어 있으면 게시 전에 **확인할 칸 N개** 라고 알려 줍니다.

## 3. 자주 하는 일

### 3-1. 소식 올리기

1. 왼쪽 **소식** → **+ 소식 추가**
2. 칸을 채웁니다.
   - **제목**, **날짜**(`2026-11-09` 처럼 하이픈), **분류**(공지·학술대회·연구 성과·수상·선정·행사·구성원)
   - **요약**: 목록 카드에 보일 한두 문장
   - **본문**: 문단 사이에 빈 줄을 하나 넣습니다.
   - **대표 사진**(선택): **사진 고르기** → JPG·PNG 파일. 긴 변 1600px 로 자동으로 줄여 저장합니다.
   - **주소 (영문)**: 날짜로 자동 제안됩니다(예: `news-20261109`). 원하면 `fall-seminar-2026` 처럼 바꿉니다. **게시한 뒤에는 바꿀 수 없습니다.**
3. 오른쪽 미리보기로 모양을 확인 → **확인하고 게시** → 바뀐 칸을 확인 → **게시하기**

> 논문·저역서를 추가하면 News 에 ‘연구 성과’ 소식이 자동으로 생기므로, 같은 내용을 소식으로 따로 올릴 필요는 없습니다.

### 3-2. 구성원 추가·수정

1. 왼쪽 **구성원** → **+ 구성원 추가** (고칠 때는 목록에서 이름을 누름)
2. **기본 정보**: 이름, 영문 이름, **과정**(박사과정·석사과정·학부생연구원·연구원·구성원), 입학·합류(`2024.03`), 공개 이메일(공개해도 되는 주소만)
3. **프로필 사진**: 세로 4:5 로 잘라 저장합니다. 본인이 게시에 동의한 사진만 올립니다.
4. **연구 관심사**(쉼표로 구분), **연구 분야**(골라서 체크), **소개**
5. **주소 (영문)**: 영문 이름으로 자동 제안됩니다(예: `seoyeon-lee`). 개인 프로필 주소 `/people/seoyeon-lee` 가 되며 나중에 바꿀 수 없습니다.
6. **확인하고 게시** → **게시하기**

### 3-3. 구성원 순서 바꾸기

People 페이지에서 같은 과정(박사·석사 등) 안의 순서는 **구성원 목록의 순서**를 따릅니다.

1. **구성원** 목록에서 각 줄 오른쪽 **↑ / ↓** 로 옮깁니다.
2. 위에 나타나는 **이 순서로 게시** 를 누릅니다. 취소하려면 **되돌리기**.

### 3-4. 졸업한 구성원을 졸업생으로 옮기기

1. **구성원** 목록에서 그 사람을 열고, 오른쪽 위 **졸업생으로 옮기기**
2. 졸업생 양식이 미리 채워져 나옵니다. 학위(박사과정 → 박사, 그 밖 → 석사)와 졸업 연도(올해)를 확인합니다.
3. **학위논문**, **현재 소속**(본인이 공개에 동의한 경우만)을 적습니다.
4. 이력·참여 연구 프로젝트에 ‘현재’로 적힌 줄(예: `2025.03 – 현재 석사과정`)은 졸업에 맞게 고칩니다.
5. 화면에 **옮기지 않는 칸**(공개 이메일·소개·연구 관심사 등)이 안내됩니다. 확인 후 **확인하고 옮기기** → **옮기기**

사진과 개인 프로필 주소는 그대로 이어집니다.

### 3-5. 프로필의 실적·수상·이력 줄 관리

구성원·졸업생 편집 화면 아래쪽 **상세 프로필** 에 네 가지 목록이 있습니다: **연구실적**, **참여 연구 프로젝트**, **수상경력**, **이력 (학력·경력)**.

- **연구실적 추가**·**프로젝트 추가**·**수상 추가**·**이력 추가** 버튼으로 줄을 더하고, **↑ / ↓** 로 순서를 바꿉니다.
- 줄마다 **사이트에 표시** 체크가 있습니다. 끄면 그 줄은 사이트에서 숨겨집니다. 줄이 여러 개면 **모두 표시 / 모두 숨김** 도 쓸 수 있습니다.
  - 숨겨도 공개 저장소에는 남습니다. 공개하면 안 되는 내용은 숨기지 말고 **지우세요**.
- **참여 연구 프로젝트** 는 **연구실 과제** 칸에서 연구 과제 목록의 과제를 고를 수 있습니다.

### 3-6. 논문·저역서·학술발표 추가

1. 왼쪽 **논문**(또는 **저역서**, **학술발표**) → **+ 논문 추가**
2. **번호는 자동**입니다. 게시할 때 종류별 가장 큰 번호 + 1 이 붙습니다(예: j62 다음은 j63).
3. 칸 채우기 요령
   - **제목·저자·학술지(출판사, 학회)** 는 원문 표기 그대로 적습니다.
   - **저자**: 제1저자부터 원래 순서대로, 쉼표로 구분
   - **날짜**: 점으로 `2026`, `2026.08`, `2026.08.15`. 모르면 비워 둡니다(‘연도 미상’).
   - **DOI·논문 페이지 주소**: 확인된 것만 적습니다. 주소는 `https://` 로 시작해야 합니다.
   - **연구 분야**: 고르지 않으면 ‘분야 미분류’로 남습니다.
   - 저역서는 **표지** 사진과 **구매 페이지 주소**, 논문은 **초록 이미지**를 넣을 수 있습니다.
4. **확인하고 게시** → **게시하기**. 연도·정렬 순서·종류별 건수는 자동으로 맞춰집니다.

항목이 12건이 넘는 목록은 위쪽 **찾기** 칸에서 제목·저자·게재지·번호로 찾을 수 있습니다.

### 3-7. 연구 과제 추가

1. 왼쪽 **연구 과제** → **+ 연구 과제 추가**
2. **과제명**, **지원 기관**, **시작**·**종료**(`2026.03` 처럼 점), **진행 상태**, **과제 구분**, 연구 분야, 과제 소개(한두 문장), 대표 이미지(선택)
3. 번호(p…)는 자동입니다. 게시한 뒤에는 구성원 프로필의 **참여 연구 프로젝트** 에서 이 과제를 고를 수 있습니다.

### 3-8. 항목 삭제

1. 항목을 열고 아래 **삭제** → 브라우저가 “삭제할까요?” 라고 물으면 **확인**
2. 공개 사이트에서 바로 사라집니다. 그 항목이 쓰던 사진 파일도 함께 지워집니다.
3. 변경 기록에는 남으므로, 실수했다면 담당자가 되살릴 수 있습니다.

> **‘예시’** 표시가 붙은 항목은 사이트 모양을 보여 주려고 넣은 가상의 내용입니다. 실제 내용을 넣은 뒤 지우세요.

## 4. 게시와 사이트 반영

1. **확인하고 게시** 를 누르면 입력을 검사하고, **바뀐 내용을 확인해 주세요** 창에서 칸마다 *지금 사이트* 와 *게시할 내용* 을 나란히 보여 줍니다.
2. **게시하기** 를 누르면 저장소에 기록되고 “게시했습니다” 가 뜹니다.
3. 위쪽 막대의 반영 상태가 **사이트에 반영하는 중…** → **사이트 최신 상태** 로 바뀌면 끝입니다(보통 1~2분).
4. 사이트에서 바로 안 보이면 **Ctrl + F5**(맥은 Cmd + Shift + R)로 새로 고칩니다.

| 반영 상태 표시 | 뜻 |
|---|---|
| 사이트 최신 상태 · N분 전 | 마지막 게시까지 사이트에 반영됨 |
| 사이트에 반영하는 중… | 검사·빌드 중. 1~2분 기다림 |
| 사이트 반영 실패 — 확인 필요 | 검사나 빌드가 실패해 **사이트는 이전 상태 그대로**. 표시를 누르면 GitHub 기록이 열림 → 담당자에게 알림 |

## 5. 이럴 땐 이렇게

| 상황 | 이렇게 하세요 |
|---|---|
| 편집 화면에 “게시하지 않은 수정 내용이 있습니다” | 전에 쓰다 만 내용이 이 브라우저에 임시 저장되어 있습니다. **불러오기** 로 이어 쓰거나 **버리기**. 다른 PC·브라우저에는 없습니다. |
| “다른 사람이 같은 칸을 먼저 수정했습니다” | 다른 칸끼리는 자동으로 합쳐집니다. 같은 칸이 겹쳤을 때만 묻습니다. **최신 내용 불러오기**(내 수정 대신 다른 사람 수정 유지) 또는 **내 내용으로 덮어쓰기** 를 고릅니다. |
| “이 저장소를 고칠 권한이 없습니다” | 초대 메일을 수락했는지 확인하고, 안 왔으면 담당자에게 초대를 요청합니다. |
| “로그인 요청이 만료되었거나 올바르지 않습니다” | GitHub 확인 화면에서 10분 넘게 머문 경우입니다. 관리 화면에서 다시 **GitHub 계정으로 로그인**. |
| “로그인이 만료되었습니다” | 8시간이 지나 자동으로 끝난 것입니다. 다시 로그인하면 쓰던 내용은 임시 저장에서 불러올 수 있습니다. |
| 사진이 안 올라감 | JPG·PNG, 30MB 이하만 됩니다. 아이폰 HEIC 사진은 JPG 로 바꿔서 올립니다. |
| “주소는 바꿀 수 없습니다” | 게시한 항목의 주소는 고정입니다. 꼭 바꿔야 하면 새로 추가한 뒤 예전 항목을 삭제합니다. |
| 잘못 게시했다 | 다시 고쳐 게시하면 됩니다. 이전 내용으로 통째로 되돌려야 하면 담당자에게 알립니다([7-5](#7-5-게시를-되돌리기)). |
| 개인 정보를 실수로 올렸다 | 관리 화면에서 지우는 것만으로는 변경 기록에서 사라지지 않습니다. **바로 담당자에게 알립니다.** |
| 위쪽에 “사이트 반영 실패” | 사이트는 이전 상태 그대로입니다. 표시를 눌러 기록 주소를 담당자에게 전달합니다. |

## 6. 올리기 전 확인

이 사이트의 저장소는 **공개**입니다. 관리 화면에 입력한 값은 사이트에 보이지 않는 칸까지 누구나 볼 수 있고, 지워도 변경 기록에 남습니다.

- [ ] 사진·이름·소속·이메일은 **본인이 공개에 동의**한 것인가
- [ ] 학번, 생년월일, 집 주소, 개인 휴대전화 같은 정보가 없는가
- [ ] 비공개 과제 정보, 심사 중인 논문 내용이 없는가
- [ ] 논문·저역서·학술발표는 원문 표기 그대로이고, 확인되지 않은 DOI·저자를 채우지 않았는가
- [ ] 확인 창에서 바뀌는 칸이 내가 고친 것과 같은가

## 7. 담당자 업무

홈페이지 담당자는 저장소가 속한 GitHub 조직 **`smu-edtech-lab`** 의 **소유자(Owner)** 입니다.

### 7-1. 편집자 초대·제거

1. 저장소 <https://github.com/smu-edtech-lab/lead-ai-lab> → **Settings** → **Collaborators and teams** → **Add people**
2. 편집자의 GitHub 아이디를 넣고 역할 **Write** 로 초대합니다. 편집자가 메일에서 수락해야 로그인할 수 있습니다.
3. 졸업 등으로 빠지는 사람은 같은 화면에서 **Remove** 합니다. 그 사람이 남긴 기록은 그대로 남습니다.

> Write 권한은 GitHub 웹사이트에서 코드 파일도 고칠 수 있는 권한입니다. 연구실 구성원 등 믿을 수 있는 사람만 초대하세요.

### 7-2. 공동 소유자 두기

소유자가 한 명뿐이면 그 사람이 떠날 때 편집자를 초대할 사람이 없어집니다. **소유자를 2명 이상** 두세요(예: 교수님 + 담당 학생).

조직 페이지 <https://github.com/smu-edtech-lab> → **People** → **Invite member** → 역할 **Owner**

### 7-3. 학기마다 점검

- [ ] 편집자 명단 정리: 졸업·휴학한 사람 **Remove**, 새로 온 사람 초대
- [ ] 관리 화면에 로그인해 보고, 소식 하나를 고쳐 게시 → 사이트 반영 확인
- [ ] ‘예시’ 표시가 붙은 항목이 남아 있지 않은지
- [ ] 로그인 중계 서버가 들어 있는 Cloudflare 계정에 담당자가 접속할 수 있는지
- [ ] 조직 소유자가 2명 이상인지

### 7-4. 담당자가 바뀔 때

[CMS-사용-안내.md 6장 체크리스트](CMS-사용-안내.md#6-담당자가-바뀔-때-체크리스트)를 따릅니다. 핵심은 세 가지입니다.

1. 새 담당자를 조직 **Owner** 로 초대
2. Cloudflare 계정(로그인 중계 서버)을 넘기거나 새 담당자를 구성원으로 초대 — 현재 값은 [CMS-설정-안내.md ‘지금 설정된 값’](CMS-설정-안내.md#지금-설정된-값-2026-11-14-26단계-완료)
3. 이 문서 위치를 알려 주기 (저장소 `docs/` 폴더, 관리 화면 위쪽 **사용 안내 ↗**)

### 7-5. 게시를 되돌리기

대부분은 관리 화면에서 다시 고쳐 게시하는 것으로 충분합니다. 한 번의 게시를 통째로 되돌려야 할 때:

1. 저장소 → **Commits** 에서 `[CMS]` 로 시작하는 해당 기록을 찾습니다(예: `[CMS] 소식 추가: 가을 세미나`).
2. 기록을 열면 무엇이 바뀌었는지 볼 수 있습니다. 그 내용을 보고 관리 화면에서 원래대로 고쳐 게시합니다.
3. 개인 정보처럼 **기록에서까지 지워야** 하는 경우는 저장소 기록을 다시 쓰는 작업이 필요하므로, 개발을 맡은 사람에게 요청합니다.

## 8. 디자인·레이아웃·고정 문구 바꾸기

### 지금은 파일을 직접 고칩니다

관리 화면은 **콘텐츠(소식·사람·연구 실적)** 만 고칩니다. 아래는 아직 관리 화면에 없어서 저장소의 파일을 고쳐야 합니다.

| 바꾸고 싶은 것 | 파일 |
|---|---|
| 연구실 이름·로고 문구 | `content/brand.json` |
| 메뉴 구성, 주소·연락처, 지원 안내(자주 묻는 질문) | `content/site.ts` |
| 지도교수 프로필·경력 | `content/profile.ts`, `content/career.json` |
| 주요 연구 분야 설명 | `content/research-areas.ts` |
| 연구실 연혁 | `content/lab-history.json` |
| 각 페이지의 문구·섹션 배치 | `app/` 폴더의 각 페이지 (`app/page.tsx` = Home 등) |
| 색·글꼴·간격 등 디자인 값 | `design-system/tokens.json` |

고치는 방법은 두 가지입니다.

1. **개발 도구로 고치기 (권장)** — 이 저장소를 내려받아 코드 편집기나 AI 코딩 도구(Claude Code 등)로 고친 뒤 `main` 에 올리면(push) 1~2분 뒤 자동으로 배포됩니다.
   배포 전에 데이터 검사와 빌드가 자동으로 돌고, 실패하면 사이트는 이전 상태로 남습니다.
2. **GitHub 웹에서 간단히 고치기** — 저장소에서 파일을 열고 연필 아이콘(**Edit this file**)으로 고친 뒤 **Commit changes**. 따옴표·쉼표·괄호 같은 기호를 지우지 않도록 조심하고, 문구 몇 글자를 바꾸는 정도에만 씁니다.

### 앞으로 관리 화면에 더할 계획

| 단계 | 내용 | 상태 |
|---|---|---|
| 1~2 | 소식·사람·연구 실적 편집 | 완료 |
| 3 | 사이트 문구 편집 (Home·About·Contact 등 페이지 문구) | 예정 |
| 4 | 디자인 값 편집 (색·글꼴·간격, 미리보기와 함께) | 예정 |
| 5 | 섹션 구성 (Home 섹션 순서·표시 여부 등 정해 둔 범위 안에서) | 예정 |

새 페이지를 만들거나 배치를 크게 바꾸는 일은 관리 화면이 생긴 뒤에도 **파일 수정**으로 합니다. 관리 화면은 사이트가 깨지지 않도록 정해 둔 범위 안에서만 바꾸게 하기 때문입니다.
